# Драйвер MongoDB у середовищі «як у Lambda»

Експеримент для нотатки `Obsidian Vault/Engineering/General/Mongo/MongoDB в AWS.md`.

Перевіряє дві речі, що впливають на кількість з'єднань і холодний старт у Lambda:

1. Скільки серверних з'єднань тримає один `MongoClient` до вузла. Специфікація моніторингу
   драйверів каже, що на FaaS-платформі (`serverMonitoringMode: auto`) драйвер переходить з
   потокового протоколу на опитування й не відкриває окреме RTT-з'єднання.
2. Скільки триває невдалий вибір сервера з типовим `serverSelectionTimeoutMS` і з коротким.

Це **не прогін у справжній Lambda**. FaaS-режим увімкнено змінною `AWS_EXECUTION_ENV`, за
якою драйвер розпізнає Lambda.

## Запуск

```bash
cd examples/mongo && npm install   # драйвер mongodb 7.7.0
./aws/run.sh                       # контейнер kbaws-mongo, порт 127.0.0.1:27093, видаляється по завершенні
```

## Результат (2026-10-30)

MongoDB 9.0 (`mongo:9`), replica set з одного вузла, драйвер Node 7.7.0, Node 24.14.1.

| Запуск | `$currentOp` з `appName` клієнта після 12 с | Невдалий вибір сервера |
| --- | --- | --- |
| звичайний процес | 3 з'єднання: пул (1), монітор, RTT | типово 30001 мс; з `serverSelectionTimeoutMS: 2000` 2002 мс |
| `AWS_EXECUTION_ENV=AWS_Lambda_nodejs24.x` | 2 з'єднання: пул (1), монітор | типово 30003 мс |

Висновок: у Lambda кожне середовище виконання тримає до кожного вузла щонайменше два
з'єднання (монітор і одне робоче), поза Lambda три. Перший прогін, де лічильник знімався
через 1,5 с, показав 2 і 2: RTT-з'єднання з'являється лише після першого heartbeat.
