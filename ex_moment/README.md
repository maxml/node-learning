# ex_moment

Лекція 5 «require. lodash. moment». Парсинг і форматування дат бібліотекою `moment`.

| Файл | Що показує |
| --- | --- |
| `index.js` | парсинг ISO 8601 у різних формах (дата, тиждень, зсув, RFC 2822), парсинг за форматом, суворий режим, створення з масиву, `get('year')`, локаль і `fromNow()` |

## Запуск

```bash
cd ex_moment
npm ci
TZ=Europe/Kyiv node index.js     # результат залежить від часового поясу машини
```

## Залежності

`moment` 2.31.0 (точна версія). До 2026-10-31 тут був `^2.24.0`: path traversal у
`moment.locale()` і ReDoS у парсингу RFC 2822 (виправлено в 2.29.2 і 2.29.4). Код не
змінювався; вивід `index.js` збігається рядок у рядок з виводом на 2.24.0. `npm audit`: 0.

## Стан на Node 24.14.1

Працює, код виходу 0. Уривок (TZ=Europe/Kyiv):

```
1995-12-25T00:00:00+02:00
2013-02-08T04:30:26+02:00      <- '2013-02-08 09:30:26.123+07:00', перераховано в локальний пояс
1995-12-25T00:00:00+02:00      <- '12/25/1995' з форматом 'MM-DD-YYYY' теж розібрано
15 years ago
```

## Відомі проблеми

- `index.js:19`: нестрогий парсинг ігнорує роздільники, тому `'12/25/1995'` проходить
  формат `'MM-DD-YYYY'`. Валідацію вводу роблять лише в суворому режимі (третій/четвертий
  аргумент `true`, як у `:21`).
- `index.js:37-39`: `moment.locale('ru')` змінює глобальну локаль лише для об'єктів,
  створених після виклику; `halloween` створено раніше, тож `fromNow()` друкує англійською
  `15 years ago` (перевірено).
- `index.js:14-16`: `dates.map` використано заради побічного ефекту, результат відкидається
  (тут доречний `forEach`).
- Сам `moment` у режимі підтримки: об'єкти мутабельні, глобальна локаль, fallback-парсинг
  через `Date`. Для нового коду: `Intl.DateTimeFormat`, `date-fns`/`Luxon`, згодом Temporal.
